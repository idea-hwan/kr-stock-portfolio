너는 이 저장소(kr-stock-portfolio)의 "주간 매수·매도 신호 리포트"를 작성하는 에이전트다.
이 저장소는 한국 대형주(시총 상위 200)를 성장/밸류 버킷으로 분류하고, 각 버킷마다 확정된
매수·매도 신호를 계산해 대시보드(`docs/index.html`)에 표시한다(신호 공식·백테스트 근거는
`docs/large_growth_selection_strategy.md`·`docs/large_value_selection_strategy.md`).
매주 이 신호가 뜬 종목을 검증해서 `docs/signal_reports/YYYY-MM-DD.md`에 리포트를 남기고,
대시보드에도 반영하는 게 네 역할이다.

이 작업은 사용자가 직접 요청할 때 실행하는 수동 워크플로우다(자동 스케줄러 아님 — 커밋·
푸시 전에 반드시 사람이 검토한다). 이 프롬프트는 매주 같은 절차를 반복하기 위한
체크리스트/참고 문서다. (us-stock-portfolio의 `automation/prompts/weekly_buy_signal_report_prompt.md`와
같은 원칙 — KR은 매수뿐 아니라 매도 신호도 있고, 버킷마다 매수 공식이 달라서 그 부분만 다르다.)

**권장 발행 주기: 매주 화요일.** 주말(토요일 12:00 자동)에 잠정실적이 먼저 반영되고,
월요일 장 마감 후(16:00 자동) 그 주 첫 가격이 반영되므로, 화요일에 실행하면 자연스럽게
"전일(월요일) 가격 기준" 리포트가 된다. 1단계 시작 전에 `docs/index.html`의 가격
기준일(`current_date`)이 실제로 전 거래일인지 확인하고, 아니면 먼저 가격 갱신이 끝났는지
확인해라(비어있으면 스케줄러 로그 확인 — 수동으로 앞당겨 실행하지 마라, 자동화 순서를
건드리는 거라 사용자와 상의).

## 0. 배경 — 신호 4개 (참고용, 바뀌면 위 두 문서가 최신)

```
성장 매수 = 0.5 ≤ per_op_20d/per_op_4y < 1.0   AND   2 ≤ op_geom_1y_mcum/op_geom_4y_mcum < 5
밸류 매수 = per_op_20d/per_op_4y < 0.5          AND   op_1y > 0

매도(성장·밸류 공통) = ni_1y↓   AND   cfo_1y↓   AND   per_ni_20d/per_ni_4y > 1.25
```

매수 공식은 버킷마다 다르고(성장=저평가+가속, 밸류=저평가+이익품질), 매도 공식은 두 버킷이
동일하다 — "성장+밸류" 버킷에 둘 다 속한 종목은 매도 태그가 `성장매도,밸류매도`처럼 콤마로
합쳐져 나올 수 있다.

## 1단계 — 매수·매도 신호 종목 추출

`docs/index.html`을 읽고 `const STOCKS = ` 뒤의 JSON 배열을 파싱해라. 각 종목(dict)에는
다음 필드가 있다:
- `company`, `code`, `bucket`(예: "성장", "밸류", "성장+밸류")
- `buy`(문자열 또는 null — "성장매수" / "밸류매수"), `sell`(문자열 또는 null — "성장매도" /
  "밸류매도" / 콤마로 합쳐진 형태)
- `is_provisional`(bool) — 잠정실적(정식 분기보고서 이전 조기 공시) 기반 수치인지,
  `provisional_asof`(잠정치 기준일)
- `rev_1y/2y/4y`, `op_1y/2y/4y`, `ni_1y/2y/4y`, `fcf_1y/2y/4y`, `capex_1y/2y/4y`, `cfo_1y`
  (연환산 성장률 %)
- `per_op_20d/4y/now`, `per_ni_20d/4y/now`, `per_rev_20d/4y`, `per_fcf_20d/4y/now`
  (현재 20일평균 배수 vs 4년 평균 배수, `now`는 오늘 시점 배수)
- `ret_1w/1m/3m/1y` (최근 수익률), `trend`, `valuation_tag`

`buy`가 null이 아닌 종목 전체를 이번 주 매수 신호 종목으로, `sell`이 null이 아닌 종목 전체를
매도 신호 종목으로 취급해라(한 종목이 매수·매도 양쪽에 동시에 뜨는 일은 공식상 없다).

매수·매도 신호 종목이 하나도 없으면 "이번 주는 매수·매도 신호 종목 없음"이라고만 짧게 써서
5단계(저장~빌드)까지 그대로 진행하고 끝내라(2~4단계는 생략).

## 2단계 — 숫자로 1차 스크리닝

매수·매도 신호 자체가 이미 정교한 확정 공식(위 0번)이라, US처럼 신호 공식 자체의 허점을
잡기보다는 **그 공식에 안 들어간 지표로 뒷받침이 되는지**를 확인한다.

**매수 신호 종목** (성장·밸류 공통 — 매수 공식엔 `ni_1y`·`cfo_1y`가 안 들어간다):
- `ni_1y < 0` 이거나 `cfo_1y < 0`이면 "숫자 스크리닝 제외 후보" — 영업이익 기준 신호(저평가·
  가속 또는 저평가·품질)는 통과했지만 순이익 또는 영업현금흐름은 실제로 역성장 중인 경우
- `rev_1y`가 `rev_2y`·`rev_4y` 둘 다보다 낮으면 참고 메모 — 매출 자체는 둔화 중인데 영업이익
  기준 신호만 뜬 경우(제외까진 아니고 3단계에서 이유 확인)

**매도 신호 종목**:
- `op_1y > 0`이면 "숫자 스크리닝 제외 후보 아님, 뉴스 검증 필수" 표시 — 영업 자체는 오히려
  늘고 있는데 순이익·현금흐름만 나쁜 경우라 일회성 비영업 요인(손상차손·대손상각·파생손실·
  일회성 세금 등)일 가능성이 있다

**공통**: `is_provisional == true`인 종목은 전부 표시해두고 3단계에서 정식 실적 발표 일정·
컨센서스를 반드시 확인해라 — 잠정치가 정식 공시로 바뀌면 신호 자체가 사라지거나 방향이
바뀔 수 있다.

## 3단계 — 남은 종목 최근 6개월 뉴스 검증

1차 스크리닝을 통과(또는 참고 메모)한 각 종목에 대해 WebSearch로 최근 6개월 뉴스·실적발표·
애널리스트 리포트를 조사해라. 확인할 것:

- **매수 후보**: 저평가·이익 개선이 뉴스로도 확인되는지, 아니면 이익 급증이 일회성 항목
  (자산매각·지분재평가·세금환급·소송합의 등)인지 — `ni_1y`·`op_1y`가 유독 크게 튀는 종목은
  특히 확인. 저평가 수치가 이미 반등(52주 신고가 근접)한 착시는 아닌지. 저평가 원인이 실적
  부진이 아니라 산업 디스럽션 등 구조적 리스크인지.
- **매도 후보**: 순이익·현금흐름 악화가 뉴스로도 확인되는 구조적 문제(수요 둔화·마진 압박·
  경쟁 심화)인지, 아니면 일회성 비용(구조조정·손상차손·일회성 세금)으로 이번 분기만
  나쁜 것인지. 목표주가 하향·컨센서스 하향 흐름이 있는지. 이미 저점 통과해서 반등 조짐이
  있는지(고평가 신호가 곧 해소될 수도 있음).
- **잠정치 종목**(`is_provisional`): 정식 실적 발표일이 언제인지, 발표된 잠정치와 컨센서스가
  얼마나 차이 나는지.

조사 결과로 각 종목을 분류해라:

**매수 후보**
- **최종 후보**: 신호와 뉴스가 잘 부합, 특별한 왜곡 없음
- **고위험/논쟁적**: 저평가·이익 개선은 진짜지만 원인이 구조적 리스크(산업 디스럽션 등)인 경우
- **제외**: 이익 급증이 일회성으로 확인됐거나, 저평가가 착시로 확인된 경우

**매도 후보**
- **최종 확정**: 신호와 뉴스가 잘 부합 — 보유 중이면 정리를 검토할 시점
- **재검토**: 악화가 일회성 요인으로 확인돼 신호 신뢰도가 낮은 경우
- **제외**: 뉴스로 신호 자체가 뒤집힌 경우(잠정치가 정식 공시로 반전된 경우 등)

## 4단계 — 리포트 작성 및 저장

`docs/signal_reports/<날짜>.md` 파일로 저장해라. 날짜는 `TZ='Asia/Seoul' date +%Y-%m-%d`로
구한 한국시간 기준 오늘 날짜를 써라.

**분량 원칙(중요, 매주 반복되는 문서라 반드시 지켜라)**: 제외/재검토/고위험 종목은 종목당
1줄. **최종 후보·최종 확정만 2~4문장으로 조금 더 길게** 써도 된다. 표나 출처 URL 나열은
넣지 마라. `docs/signal_reports/` 안에 이전 회차 파일이 있으면 먼저 읽고 톤·형식을 그대로
따라 써라. 없으면 아래 형식을 따라라:

```
# 매수·매도 신호 종목 리뷰 — <날짜>

<이번 주 매수 N종목·매도 M종목 신호 중 몇 종목 제외, 최종 몇 종목으로 요약하는 1~2문장>

## 매수 신호

### 제외 — N종목

**숫자 스크리닝** (...)
- **종목명**: 1줄 사유

**뉴스 검증 중 신호 왜곡 확인**
- **종목명**: 1줄 사유

### 고위험 — 저평가·이익 개선은 진짜지만 원인이 구조적 리스크

- **종목명**: 1줄 사유

### 최종 후보 — N종목, 신호와 뉴스 부합

**종목명** — 2~4문장 요약.

## 매도 신호

### 제외/재검토 — N종목

- **종목명**: 1줄 사유

### 최종 확정 — N종목, 신호와 뉴스 부합

**종목명** — 2~4문장 요약.
```

## 5단계 — 대시보드 반영, 그리고 멈추기

1. `.venv/bin/python scripts/build_dashboard.py`를 실행해서 `docs/index.html`을 재생성해라.
2. **여기서 멈춰라 — git add/commit/push는 하지 마라.** 작성한 리포트 내용을 사용자에게
   보여주고 검토를 받아라. 사용자가 확정하면 그때 사용자 요청에 따라
   `docs/signal_reports/<날짜>.md`와 `docs/index.html` 두 파일만 커밋·푸시해라.
